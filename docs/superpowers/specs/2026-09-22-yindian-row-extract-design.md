# 音典字表特殊记录与词表候选提取设计

## 目标

为 `build.py` 增加音典特殊记录和词表候选提取能力：

- `-v, --vocabulary`：从 `data/raw/pull_yindian/` 的音典 TSV 中提取汉字字段包含方框占位符的记录。
- `-n, --note`：从同一批 TSV 中提取解释/注释字段非空的记录。
- `-w, --word`：从现代真正的 `#漢字` 字表中按地点提取词表候选。
- `scripts/yindian_llm.py`：从选定地点的原始 `#漢字` 字表中逐行送入 DeepSeek；请求可以批量发送，但每行独立分析。该流程独立于 `build.py`。

三个提取参数可以单独使用，也可以组合使用；它们不参与数据库写入。独立的
`scripts/yindian_llm.py` 也不参与原有数据库流程。

## 输出

每个输入地点保持独立文件，不合并地点，也不修改原始拉取目录：

```text
data/raw/extract/
├── vocabulary/
│   └── <地点>.tsv
└── note/
    └── <地点>.tsv
```

输出文件沿用输入文件名和原始 TSV 表头，保留原始行的全部列。没有匹配记录的地点不生成空文件；每次执行会清理对应的提取目录后重新生成，避免保留过期结果。

词表候选单独输出到：

```text
data/raw/extract/word/
└── <地点>.tsv
```

词表候选文件使用以下列：

```text
标准词    方言词    音标    注释    type    原始汉字    来源文件    原始行号
```

`标准词`第一版始终留空，供后续 LLM 或人工补充。

LLM 输入和结果输出到：

```text
data/raw/extract/word_llm/
├── input/<地点>.jsonl
├── result/<地点>.jsonl
├── result/<地点>.errors.jsonl
├── xlsx/<地点>.xlsx
└── manifest.json
```

输入每条只包含原始汉字、完整原始注释、来源文件和原始行号，不包含音标、机械替换候选、`type` 或元数据。模型输出每条只包含 `id` 和 `entries`，每个 entry 只包含方言词、标准词候选和置信度。

执行入口：

```bash
python3 scripts/yindian_llm.py run --points 泉州,蘇州東村,南寧 --batch-size 20 --workers 4 --reset
```

脚本优先读取环境变量 `DEEPSEEK_API_KEY`，没有时自动读取项目根目录 `.env` 中的
`DEEPSEEK_API_KEY` 或兼容的 `deepseek-api-key`。`.env` 不提交到 Git。

## 匹配规则

### 方框字表

汉字字段只要包含预定义的方框占位符集合中的任一字符就匹配。集合覆盖常见空白方框、黑方框、勾选框、实心块和替换字符，包括 `□`、`■`、`⬜`、`⬛`、`☐`、`☑`、`☒`、`▯`、`▢`、`▣`、`█`、`�`。

### 注释

解释/注释字段去除首尾空白后仍非空即匹配。字段名兼容音典常见命名：`解釋`、`解释`、`注釋`、`注释`、`notes`。

### 词表候选

只扫描表头为 `#漢字` 或 `#汉字` 的现代字表；`#詞語` 等词语表不纳入。文件名以四位年份开头，或包含以下历史音、字典、韵书及非方言材料标识时排除：`清末`、`歷史`、`历史`、`上古`、`中古`、`古音`、`字典`、`漢大`、`康熙`、`說文`、`廣韻`、`集韻`、`匯纂`、`蒙古字韻`、`分韻撮要`、`西儒耳目資`、`日語`、`中唐`、`北宋`、`盛唐`、`普通話`、`國語`；`固原`也明确排除。

词表候选包含所有带非空注释的记录，不丢弃方框字：

- 注释包含 `~` 或 `～`：`type=tilde`，将全部标记替换为该行原始汉字，得到 `方言词`。
- 注释不包含标记：`type=note`，保留完整注释，但 `方言词` 留空，等待人工或 LLM 审查，不凭注释自由猜词。

上述 `-w` 是独立的机械候选提取功能；`scripts/yindian_llm.py` 不读取其输出，也不使用其中的 `~` 替换结果。

## 执行时机

- 带 `-m full` 或 `-m diff` 时：先完成音典数据拉取，再执行提取。
- 不带 `-m` 时：直接扫描当前已有的 `data/raw/pull_yindian/`。
- 只有 `-v`、`-n`、`-w` 或它们的组合时：提取结束后直接退出，不触发默认数据库写入。
- 若同时传入 `-t` 或 `-c`，提取完成后继续执行原有任务。

## 测试

测试覆盖：

1. 多种方框字符都能被提取。
2. 带注释和空注释行的筛选边界。
3. 每个输入地点独立输出，表头与原始列保留。
4. 无匹配地点不生成文件，并在重复执行时清理旧结果。
5. CLI 能解析提取开关，且提取开关不会触发默认写库。
6. 现代 `#漢字` 文件能提取词表候选，`~` 行能恢复方言词，普通注释行能保留且标记为 `note`。
7. `#詞語`、固原和历史/韵书文件不会进入词表候选输出。
8. `scripts/yindian_llm.py` 从原始文件读取全部带注释行，不发送音标或机械候选。
9. 独立脚本从原始文件读取全部带注释行，不依赖 `-w` 的机械候选输出。
10. LLM 批量返回时，每个输入 `id` 都必须独立返回；一个输入可以有多个词条。
